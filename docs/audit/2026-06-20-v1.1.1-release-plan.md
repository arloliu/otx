# otx v1.1.1 — patch-release plan

**Date** 2026-06-20
**Type** patch (backward-compatible, SemVer `1.1.0 → 1.1.1`)
**Method** 21 area auditors across 5 dimensions (bug-fix, error-handling, robustness, code-simplification, doc-correctness), each finding independently re-verified against current source at HEAD by an adversarial reviewer, then triaged against the v1.1.1 patch-scope contract.

**SCOPE.** A patch release MAY contain only: (a) backward-compatible bug fixes; (b) internal error-handling / robustness hardening that changes no exported signature and no documented / observable / on-the-wire behavior; (c) pure code simplification with byte-identical behavior; (d) documentation corrections. It MUST NOT add any new exported symbol, change any existing exported signature, alter any documented or on-the-wire behavior or default value (even a "more correct" one), introduce a new feature, or add a dependency. One narrow exception applies: fixing a genuine **defect** (panic, goroutine leak, data race, crash, or output so wrong no caller could intend to rely on it) is in scope even though it technically changes behavior — because the prior behavior was a bug. Every such item is flagged `behavior_change=true` with a note that the prior behavior was a defect.

Overall code health is strong: of 63 in-scope findings, 49 (78%) are pure documentation corrections and 7 are byte-identical code simplifications, leaving only 7 findings (4 bug-fix + 3 robustness) that touch runtime behavior — and every one of those is either internal hardening or a genuine defect fix with no impact on the exported library surface. The dominant theme is **documentation drift**: copy-paste-broken godoc/README/guide snippets (wrong package aliases, missing imports, nonexistent symbols), examples steering users at deprecated config blocks/symbols, and `telemetry:`-wrapped YAML that silently parses to a disabled config. The second theme is the **`cmd/otlp-sim` dev CLI**, which concentrates almost all of the behavioral defects (flag parsing, ticker panic, missing shutdown/flush, inverted env precedence) — none of which touch the otx library API. The single highest-severity item is the README "Middleware" section, which references an entire nonexistent package.

## In scope for v1.1.1

### Bug fixes

**BUG-1 — Bare `--insecure` flag silently swallows the following argument** *(medium, high)* — `cmd/otlp-sim/config.go:55-60`
`--insecure` is registered with `fs.Func`, making it value-requiring: bare `--insecure` consumes the next token as its value (e.g. `--insecure --endpoint localhost:14317` sets Insecure from the string `"--endpoint"` and silently drops `--endpoint`/`--count`). Usage text documents it as a boolean. Fix: change `fs.Func("insecure", ...)` to `fs.BoolFunc("insecure", ...)`, keeping the callback body byte-identical (`val := s == "true" || s == "1"; c.Insecure = &val; return nil`); `--insecure=false/true/1` continue to parse as before. *Backward-compatible for the explicit `--insecure=<v>` form; `behavior_change=true` for the bare form — prior bare-flag behavior was a defect. Confined to the otlp-sim CLI; no library API touched.*

**BUG-2 — `Engine.Shutdown` is never called: batched spans/logs lost, export-error summary never prints** *(medium, high)* — `cmd/otlp-sim/main.go:149-188, 191-236`; `engine/engine.go:133-158`
`executeQuick` and `executeContinuous` create an engine via `engine.New` but never call `eng.Shutdown`. The tracer provider uses a `BatchSpanProcessor` and the logger provider a `BatchProcessor`, so buffered spans/logs at exit are dropped; the `executeQuick` 500ms sleep waits but does not flush (default batch delay is 5s). `errorHandler.Summary()` prints only from `Shutdown`, so the export-error summary never fires. Fix: add a deferred bounded shutdown (using a fresh `context.Background()`, since SIGINT cancels `ctx`) after each successful `engine.New` check in both functions; the 500ms quick-mode sleep may be dropped. *No exported API or signature change; `behavior_change=true` but prior no-flush behavior was a defect (silent data loss + dead error reporting). Confined to the otlp-sim CLI.*

**BUG-3 — `WithTransport(nil)` drops all transport-level options and bypasses the default-transport clone** *(low, high)* — `http/client.go:118-122` (interacts with `buildTransport` at `http/client.go:217-233`)
`WithTransport`'s godoc says "nil leaves the default in effect", but the body unconditionally does `c.baseTransport = rt`, overwriting the seeded `http.DefaultTransport` with nil. `buildTransport` then returns nil verbatim before applying any pool/timeout options, and the salvage path in `Transport` wraps the shared global `http.DefaultTransport` instead of a clone — so `NewClient(WithTransport(nil), WithMaxIdleConns(7))` silently ignores `MaxIdleConns`. Fix: add a nil guard so the option no-ops on nil: `func WithTransport(rt http.RoundTripper) ClientOption { return func(c *clientConfig) { if rt == nil { return }; c.baseTransport = rt } }`. *No signature change; `behavior_change=true` but the prior `WithTransport(nil)` output contradicted its own godoc and is a defect no caller could intend to rely on. Backward-compatible for all non-nil callers.*

**BUG-4 — Documented env var `OTEL_EXPORTER_OTLP_PROTOCOL` is silently ignored** *(low, high)* — `cmd/otlp-sim/main.go:73` (usage); `cmd/otlp-sim/config.go:15`
`printUsage` advertises `OTEL_EXPORTER_OTLP_PROTOCOL grpc or http` as honored, but `Config.UseHTTP` has no `env:` tag and nothing reads that variable; protocol is set only via `--http`. Fix (doc-only, patch-safe): delete the `OTEL_EXPORTER_OTLP_PROTOCOL` line from the Environment Variables block in `printUsage`. Honoring the variable for real would introduce new env-handling behavior and is deferred. *Backward-compatible; corrects untrue help text only — no API or observable behavior change.*

### Robustness

**ROB-1 — zaplog OTLP core never warns on plaintext export to a non-loopback host** *(medium, high)* — `zaplog/core.go:105,111,146-150`; cf. `exporter.go:94-122` `warnInsecureRemote`
The SDK trace/metric/log exporters call `warnInsecureRemote` (a v1.1.0 hardening) to emit a one-time `otel.Handle` diagnostic when `Insecure` is unset/true against a non-loopback host. `zaplog.NewCore` consumes the identical insecure/endpoint inputs (`base.IsInsecure()` defaults TRUE; `buildEndpoint` prefixes `http://`) but emits no such warning, so a remote zaplog endpoint left default-insecure with bearer headers ships logs and credentials in cleartext silently — the exact leak v1.1.0 closed for traces/metrics. `config.go:86-92` documents the diagnostic as if it already fires for this path, making it also a doc-consistency defect. Fix: after resolving protocol/endpoint in `NewCore`, classify the effective endpoint (zaplog already imports `internal/endpoint`; `Classify` is exported) and, when insecure AND non-loopback AND not `https://`, emit the same one-time `otel.Handle` diagnostic — keep it internal-only (no new exported symbol). Preferred: lift the existing `warnInsecureRemote`/`isLoopbackEndpoint`/`insecureWarned` dedup-map logic into a small unexported shared internal package (e.g. `internal/insecurewarn`) called from both `exporter.go` and `zaplog`, so a shared endpoint warns at most once per process. Add a new zaplog test asserting the WARN fires for a remote bare insecure endpoint and stays silent for loopback and `https://`. **Implementation note:** the dedup-map extraction touches `exporter.go`'s existing call sites — verify `exporter.go`'s current trace/metric/log warning behavior stays byte-identical after the lift (run the existing exporter-path tests as a regression check, not just the new zaplog test). *`requires_new_api=false`; `behavior_change=true` (adds WARN output only — no signature/wire/default change); mirrors v1.1.0 hardening on a documented footgun.*

**ROB-2 — `run --rate 0` (or negative/tiny rate) panics: non-positive interval for `NewTicker`** *(medium, high)* — `cmd/otlp-sim/main.go:211-212`
`interval := time.Duration(float64(time.Second) / cfg.Rate)` with an unvalidated user `--rate`: `--rate 0` → `+Inf` → negative duration → `time.NewTicker` panics; negative and tiny-positive rates panic the same way, crashing the binary. Fix: compute `interval`, then guard `if interval <= 0 { return fmt.Errorf("rate %v yields a non-positive interval", cfg.Rate) }` (covers 0, negative, and tiny-positive overflow in one check); the existing caller prints the returned error cleanly. *`behavior_change=true` but the prior panic was a defect. Backward-compatible for all valid rates (>0). Confined to the otlp-sim CLI `run` mode.*

**ROB-3 — Env vars override explicit CLI flags (inverted precedence)** *(medium, high)* — `cmd/otlp-sim/main.go:94,118`; `cmd/otlp-sim/config.go:67-71`
`applyEnvOverrides()` (`fuda.LoadEnv`) runs *after* `fs.Parse`, so a set `OTEL_EXPORTER_OTLP_ENDPOINT` / `OTEL_EXPORTER_OTLP_INSECURE` / `OTEL_SERVICE_NAME` silently overwrites an explicit `--endpoint` / `--insecure` / `--service-name`. Conventional precedence is CLI > env > default; this tool does env > CLI > default. Fix: in both `runQuickMode` and `runContinuousMode`, move `cfg.applyEnvOverrides()` to immediately after `cfg := newConfig()` and *before* `cfg.bindCommonFlags(fs)`/`fs.Parse` — order becomes defaults → env → flag-seeding → explicit flags win last. The `--insecure` func only mutates when the flag is present, so an explicit `--insecure` still wins. Optionally add a regression test asserting `--endpoint` beats `OTEL_EXPORTER_OTLP_ENDPOINT`. *`behavior_change=true` but a user typing `--endpoint` cannot intend it to be silently ignored — the prior precedence was a defect. Confined to the otlp-sim CLI.*

### Code simplification

## Validation gate

Run the full gate before **every** commit (per `AGENTS.md`):

1. `go fix ./<changed-pkg>/...` — touched packages only.
2. `make lint` — fix all issues. **Never** invoke `golangci-lint` directly and never edit `.golangci.yaml`.
3. `make test` — must pass. It runs `go test -race ./...` over the root module **and** the nested integration module (`nats/internal/integration`, embedded NATS server), so `-race` and the integration suite are always exercised.
4. `make lint-integration` — lints the nested module (`make lint` does not descend into it); required for any change touching `nats/internal/integration`.
